# Flutter 实施路线

产品范围来自制作包的 `01_产品方案/产品方案.md`，里程碑与验收来自 `09_实施计划/实施计划.md`。外层 PDF 与包内 PDF 哈希相同，没有第二套实施计划。本路线沿用 M0–M7 顺序，技术栈按用户明确要求采用 Flutter。

## 实现选择

制作包的 Capacitor 是【建议】，其理由是保留 Three.js 动作核心。当前同样保留 v33 动作算法，Flutter 负责页面、导航、训练计时、本地持久化和平台适配，3D 使用随安装包提供的局部 Web 场景。浏览器嵌入同源 iframe；Android/iOS 使用 WebView 和本机 loopback 资产服务。后续可依据真机效果调整渲染方案，动作硬规则、自然人体、离线和零预算约束继续生效。

源版产品的“看 → 懂 → 练 → 测 → 解锁”贯穿各阶段。V1 的“测”先采用人工计时/计数与自评；AI 属于 v1.1，不用占位评分替代已验证能力。

## 下一轮顺序

先在 Android 真机检验本地加载、人物全身构图、暂停点选及返回同帧，决定质量档与网格复杂度是否继续调整。正背同步小人体已接入；随后完成 M1/M2 的手机性能和人工点选表，补齐 M3 原生计时支持，再审核 M4 教学草稿和 M5 数据操作。M6 按后续版本开展，M7 的发布动作以可审阅的真实构建包为前提。

开发默认零预算：使用已有成熟模型与合法免费工具，继续免费提供本地训练。制作包中的价格、试用天数、收入指标和耗时只是建议或示意。真实订阅、公开部署、推送和商店上传在成品可审阅后按用户授权处理；当前不会为了补图调用付费生成服务。
