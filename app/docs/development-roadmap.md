# Flutter 实施路线

产品范围来自制作包的 `01_产品方案/产品方案.md`，里程碑与验收来自 `09_实施计划/实施计划.md`。外层 PDF 与包内 PDF 哈希相同，没有第二套实施计划。本路线沿用 M0–M7 顺序，技术栈按用户明确要求采用 Flutter。

## 实现选择

制作包的 Capacitor 是【建议】，其理由是保留 Three.js 动作核心。2026-10-09已按新包推荐改为v38烘焙GLB与AnimationMixer，v33算法保留为历史基线，Flutter 负责页面、导航、训练计时、本地持久化和平台适配，3D 使用随安装包提供的局部 Web 场景。浏览器嵌入同源 iframe；Android/iOS 使用 WebView 和本机 loopback 资产服务。后续可依据真机效果调整渲染方案，动作硬规则、自然人体、离线和零预算约束继续生效。

源版产品的“看 → 懂 → 练 → 测 → 解锁”贯穿各阶段。V1 的“测”先采用人工计时/计数与自评；AI 属于 v1.1，不用占位评分替代已验证能力。

## 2026-10-09 精简重构

全页面按设计稿重构（详见 verification.md 顶部与 redesign-plan-2026-10-09.md）：详情页托马斯原服装上直接显示肌群色、固定全身机位禁止旋转缩放；每页一个主体一个主按钮。待真机复看高亮观感与计时前台倒数。

## 下一轮顺序

接手先复测训练前台倒数、暂停/继续、完成与本地保存，确认本次 IAB 倒数停留现象的范围，再运行当前v38版本（首页穿衣、详情米白模特），对照真实截图核对首页、暂停详情和小卡片交换。在 Android 真机检验本地加载、人物全身构图、暂停点选及返回同帧，决定质量档与网格复杂度是否继续调整；随后完成 M1/M2 的手机性能和人工点选表，补齐 M3 原生计时支持，再审核 M4 教学草稿和 M5 数据操作。M6 按后续版本开展，M7 的发布动作以可审阅的真实构建包为前提。本次按最新明确要求恢复米白哑光模特，只在指定肌群详情展示；相对教学坐标 `mmRest` 用于点击与本群组柔边色区，不声称精确解剖配准。

开发默认零预算：使用已有成熟模型与合法免费工具，继续免费提供本地训练。制作包中的价格、试用天数、收入指标和耗时只是建议或示意。2026-10-08按用户要求完成旧检查点保存、提交、远程同步及14类界面截图；本次保存v38更新的本地可审阅成果和3张受影响界面图。阶段保存不表示已完成真机、生产签名、订阅、公开站点部署或商店上传；生产发布按用户具体安排处理，不为补图调用付费生成服务。
