给 Mac 端负责人的交接说明，照着从上往下做即可。基线是 `master` 812d948（PR #7 合并后）加上分支 `dev/hark` 的 iOS 准备提交（见第 1 节）。进度和问题记在第 6 节的验收记录里；代码问题回报给 Hark 修，Mac 端只需要按步骤构建、测试、截图。

## 0. 目标与范围

- **v1 目标**：iPhone 上和当前 Android 版功能一致：3D 托马斯循环、暂停与肌群详情、训练库与计时、路径、记录、深浅主题。离线运行，没有账号，不联网。
- **不做**：iPad 专版（v1 只支持 iPhone）、M6 AI/相机、云同步、内购。
- **原则**：同一份 Flutter 代码、同一个 3D 场景（`app/assets/scene/`），不为 iOS 单独开分支或单独实现。iOS 上发现问题，先在共用代码里修，再回归 Android。
- **完成标准**：第 5 节的 A 级验收全部通过，并有 TestFlight 包（如果开通了付费开发者账号）或真机 Release 安装包。

## 3. 环境与命令

```bash
# 1) 拉代码（Windows 主目录对应 E:\AII-3D\3D-Body；Mac 新克隆即可）
git clone https://github.com/mhgd3250905/3D-Body.git && cd 3D-Body && git checkout master
# 2) Flutter 版本与项目基线一致：3.47.6（推荐 fvm：fvm install 3.47.6 && fvm use 3.47.6）
# 3) 自检（Xcode ≥16、Flutter 版本、模拟器、plist、pub get）
bash app/tools/ios/doctor.sh
# 4) 常用
bash app/tools/ios/build.sh check          # analyze + 单元测试
bash app/tools/ios/build.sh sim            # 模拟器 Debug 构建，不需要签名
bash app/tools/ios/build.sh smoke <设备ID>  # 3D 冒烟测试（flutter devices 查看设备 ID）
bash app/tools/ios/build.sh device         # Release 装到连接的 iPhone
bash app/tools/ios/build.sh ipa            # TestFlight 包（需要 D1 + 填写 teamID）
```

- **不需要 Node**：3D 场景的构建产物已经提交在 `app/assets/scene/`。只有改 `app/scene/src` 才需要 Node 22 加 `npm ci && npm run build && npm run verify`，这部分由 Hark 负责。
- 工程用 Flutter 的 Swift Package Manager 集成，没有 Podfile。如果 Flutter 提示需要 CocoaPods，按提示安装（`brew install cocoapods`），**不要**手动改 `ios/Flutter/` 下的生成文件。
- 每次运行 flutter 命令后，`app/analysis_options.yaml` 可能被改写，提交前用 `git checkout app/analysis_options.yaml` 还原（脚本会自动还原）。
- 国内网络慢：`export PUB_HOSTED_URL=https://pub.flutter-io.cn FLUTTER_STORAGE_BASE_URL=https://storage.flutter-io.cn`。
- 调试 3D 网页：先用 Debug 包运行，然后在 Mac Safari 菜单栏选“开发”→ 你的设备 → `127.0.0.1` 页面，可以看控制台报错和 WebGL 状态。需要在 iPhone 的“设置 → Safari → 高级”里打开“网页检查器”。

## 4. 任务清单（按顺序做，每项做完就填第 6 节）

估时按一名熟悉 Xcode 的开发者计算。

### I01 首次构建与模拟器运行（0.5 天）
1. `doctor.sh` 全部通过。
2. `build.sh check` 通过：73 个单元测试全过，analyze 无问题。
3. `build.sh sim` 成功，`flutter run -d "iPhone 16"`（或任意新机型模拟器）能启动。
4. 首启流程（安全提示 → 首页）能走通，3D 托马斯能在首页循环播放。
- **完成标准**：模拟器上的首页截图和 Android 截图（`docs/screenshots/2026-10-09-pr7-audit/home.png`）构图一致。
- **常见问题**：编译时报签名错误 → 模拟器不需要签名，确认选的是模拟器目标；报 SwiftPM 解析失败 → `flutter clean && flutter pub get`，再在 Xcode 里 File → Packages → Reset Package Caches。

### I02 签名与真机安装（0.5 天）
1. 在 Xcode 打开 `app/ios/Runner.xcworkspace` → Runner target → Signing & Capabilities → 勾选 Automatically manage signing，选择 Team（免费账号显示为 Personal Team）。
2. Bundle ID 按 D2 填写。
3. iPhone 连接 Mac，在 iPhone 上打开“设置 → 隐私与安全性 → 开发者模式”，`build.sh device`。
4. 首次运行后，在 iPhone 上信任开发者：“设置 → 通用 → VPN 与设备管理”。
- **完成标准**：真机 Release 包从桌面图标冷启动，能看到首页 3D。**不要把签名改动提交到仓库**（Team ID 属于个人信息；`DEVELOPMENT_TEAM` 只留在本机）。

### I03 3D 场景加载（WKWebView + 127.0.0.1）（0.5 天）
1. 在模拟器和真机上各跑一次 `build.sh smoke <设备>`，记录 `sceneReadyMs`。
2. 打开飞行模式，冷启动后 3D 仍能加载（证明完全离线）。
3. 用 Safari Web Inspector 确认控制台没有红色错误，WebGL 上下文是 webgl2。
- **完成标准**：smoke 测试通过；真机 `sceneReadyMs` ≤ 4000 ms（中端机，冷启动后第一次）；飞行模式下正常。
- **如果加载失败**：先看 Inspector 网络面板，`/assets/...` 是否返回 200。如果被 ATS 拦截，把截图和报错回报给 Hark，**不要**改成 `NSAllowsArbitraryLoads`。

### I04 触摸与手势（1 天）
逐项操作，每项录屏：
1. 首页单指拖动可以旋转托马斯，松手后有惯性；双指可以缩放。
2. 点击肌群热点能进入详情，**镜头是一段连续的弧线滑动，模型不跳位置、不突然变大小**（Android 第二批问题 #8）。
3. 详情页**直接返回**也有过渡动画（第二批 #9），拖动之后再返回也一样。
4. 详情页的托马斯：单指可以朝各个方向旋转，双指**不能**缩放。直立人台可以自由旋转。
5. 长按 3D 区域 2 秒：不出现选择文字、放大镜、链接预览、“拷贝”菜单，也没有灰色点击高亮（第一批 #1）。
6. 3D 区域上下快速拖动，网页本身不回弹、不露出白边。
7. 左缘返回手势（训练详情等二级页面）可以用；在 3D 舞台和计时页上没有左缘返回，也不会被 WebView 吞掉。
8. 底部的阶段条、播放按钮、详情面板上的按钮，点击都能响应，不会把点击漏给后面的 3D。
- **完成标准**：8 项全部通过；任何一项失败都按第 7 节的格式回报。

### I05 布局与安全区（0.5 天）
设备：iPhone SE（第 3 代，4.7 英寸）、带刘海的 iPhone（如 13）、带灵动岛的 iPhone（如 15/16 Pro），模拟器即可。
1. 顶部标题不被刘海或灵动岛挡住；底部按钮不压在 Home 指示条上。
2. SE 小屏上详情面板文字不截断，训练详情大图不变形。
3. 系统“设置 → 显示与亮度 → 文字大小”调到最大一档：主要页面不溢出（允许换行）。
4. 横屏（按 D3）：不崩溃，内容可见。
- **完成标准**：3 个机型深色和浅色各截首页、详情、训练详情、计时，共 24 张截图，放进 `docs/screenshots/ios-<日期>/`。

### I06 主题、状态栏、启动屏（0.25 天）
1. 冷启动全程没有白闪，启动屏是深色 #08080A。
2. 设置里切换深色/浅色/跟随系统：整屏淡入过渡（360ms），3D 区域外壳颜色同步变化；状态栏图标颜色跟着主题变（浅色主题显示黑色图标）。
3. App 运行时在控制中心切换系统深浅色，“跟随系统”立即生效。
- **完成标准**：录屏 1 段。

### I07 生命周期与稳定性（1 天）
1. 首页播放时按 Home 键退到后台，30 秒后回来：画面正常，暂停在离开时的帧（或继续播放，和 Android 一致）。
2. 锁屏 5 分钟后解锁回到 App：3D 正常。
3. 详情页里切到后台，再打开 3 个大型 App（相机、地图、游戏）后切回来：如果网页进程被回收，应该**自动**重新加载，并回到同一个详情页和同一帧，不出现错误卡片。
4. 模拟器上：Debug → Simulate Memory Warning；再用 Mac 的“活动监视器”强制退出 `com.apple.WebKit.WebContent` 进程，App 应在 1–2 秒内自动恢复 3D。1 分钟内再杀一次，应显示错误卡片，点“重试”能恢复。
5. 通话或闹钟打断（真机）：回来后不崩溃。
6. 连续使用 20 分钟（首页 ↔ 详情来回 30 次、训练计时 2 组）：不崩溃，不卡顿。
- **完成标准**：6 项通过；第 4 项附录屏。

### I08 训练计时（T01 的 iOS 部分）（0.5 天）
1. 选一个训练：准备 → 工作 → 休息 → 完成，倒数正常走，不会停在 3 秒。
2. 计时中切到后台 1 分钟再回来：按当前设计（`suspendForBackground`），离开时计时会暂停，回来后手动继续；确认行为和 Android 一致，回来后时间没有跳变。
3. 完成后记录页出现这次训练，杀掉 App 再打开，记录还在。
- **说明**：屏幕常亮、提示音、后台通知属于 M3 原生能力，两个平台都还没做，**这次不验收**。

### I09 性能（1 天）
设备：一台中端旧机（iPhone 11/12/SE 3 级）和一台新机。
1. Xcode 连接真机 → Debug Navigator → FPS（或 Instruments → Core Animation / Metal System Trace），首页循环播放 60 秒。
2. 进出详情 10 次，看镜头过渡时有没有掉帧。
3. Instruments → Allocations/VM Tracker，记录首页稳定后的内存峰值（App 进程加 WebContent 进程）。
4. 冷启动到首页 3D 出现的时间（录屏数帧，或用 `sceneReadyMs`）。
5. 连续播放 10 分钟，机身温度（主观描述，设置里没有出现“温度过高”提示即可）。
- **完成标准**：旧机首页平均 ≥ 45 fps，新机 ≥ 55 fps；内存峰值 ≤ 600 MB；冷启动到 3D ≤ 5 秒（旧机）。达不到就把数据和 trace 文件回报给 Hark，**不要**自己降画质。画质档位在 `scene/src/player.js` 的 `QUALITY` 里，统一调。

### I10 触感（0.25 天）
真机（模拟器没有震动）：点选肌群、切换分段控件、开始和完成计时，都有轻微触感，而且不刺耳。和 Android 对比后描述强弱差异。

### I11 无障碍（0.5 天）
1. 打开 VoiceOver：首页主要按钮、肌群列表、详情返回、训练开始，都能读出中文名称并操作。
2. 打开“减弱动态效果”：页面和镜头过渡变成淡入或直接切换，加载动画不转圈。
- **完成标准**：问题清单（允许有问题，但要记录）。

### I12 发布准备（D1 通过后再做，1 天）
1. App Store Connect 新建 App：名称“Flare 托马斯”（如果被占用，就用“Flare 托马斯全旋”），主语言简体中文，Bundle ID 按 D2。
2. App 隐私：选择“不收集数据”（与 `PrivacyInfo.xcprivacy` 一致）。
3. 年龄分级：4+（无不当内容）。在审核说明里写明：离线教学 App，3D 资产在本机通过 127.0.0.1 加载，不访问外网。
4. 在 `tools/ios/ExportOptions.plist` 填写 teamID（**不要提交**），然后运行 `build.sh ipa`，用 Transporter 或 Xcode Organizer 上传。
5. TestFlight 内部测试：至少 2 台设备装上，把 I03、I04 再快速跑一遍。

## 8. 风险与预案

| 风险 | 表现 | 预案 |
|---|---|---|
| WKWebView 内存上限 | 后台或长时间使用后 3D 空白 | 已有自动恢复（I07-3/4）；如果频繁出现，Hark 会降低详情的纹理和阴影精度 |
| ATS 拦截 127.0.0.1 | 首次加载失败 | 已配置 `NSAllowsLocalNetworking`；不行再按 I03 回报，不要放开全局 HTTP |
| 回到前台后本机服务端口失效 | 回前台后新请求失败（场景已加载时一般不会再请求资源） | 自动恢复会重建服务和 WebView；I07 专门测 |
| ProMotion 120Hz 发热 | 新机发热、耗电快 | I09 记录；需要时由场景统一限制到 60fps |
