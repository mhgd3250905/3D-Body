## SDK 待完善清单

本轮只记录并使用公共 API 适配，未修改 SDK 仓库或缓存源码；尚未向 SDK 仓库提交 issue/PR。

1. **播放器缺少宿主训练操作插槽**：`TrainerPlayer` 没有逐次手点计数、延长休息或提前完成 timed work 的公开控制入口。FlareLab 保留自身训练页，用 `SessionEngine` 驱动；SDK 可增加控制器/controls slot，以便后续直接使用完整播放器。
2. **引擎缺少延长休息和提前完成定时段 API**：当前通过公开 `SessionRunner.restartWith` 保留相位访问与身份，再完成/替换当前余量。建议提供明确的 `extendRest` / `completeTimedSet`，减少宿主适配。
3. **多段动作完成身份**：SDK 以 item/set/side 识别完成，Y/T/W 等需映射为独立 item 再聚合组数。建议明确 segment 身份或正式支持分段编排，避免重复身份导致提前完成。
4. **口令默认右侧先行**：SDK 内置脚本以 right 作为 firstSide；FlareLab 的左先行要求通过 VoiceSource 语义适配保留正确提示。建议脚本从实际首侧/相位顺序推导，避免播放“先做右侧”。
5. **小数时间相位边界的浮点容差**：SDK `SessionEngine.update` 使用严格的 `t - phaseStart >= seconds`。当宿主为避免跨段补记而把时间夹到当前段末，例如 `phaseStart = 3.001`、`seconds = 3`、`t = 6.001`，浮点减法得到 `2.9999999999999996`，会停留在倒计时。App 现仅在已到段末时给公开 `SessionRunner.update` 的探测时间加 `1e-9` 秒，记录时钟仍精确夹在段末，不向下一练习补记超时；新增确定性回归覆盖该值。建议 SDK 在相位结束比较中采用明确的浮点容差，避免不同真实毫秒起点造成间歇停滞。

资源覆盖另列：现有可复用公共口令主要为中文，其他语言录音尚缺；这不是 UI 翻译缺失。录音源使用 Edge read-aloud 的既有素材，原来源文档明确商业用途条款未确认，本批次按内测素材登记，商店发布前另行处理。
