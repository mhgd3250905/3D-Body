# 手动摆放托马斯中间姿势

打开本地网页默认进入“动作分解”，暂停在正式循环起点——原第 09 步后双撑。切换导航中的“姿势编辑”会恢复已有草稿；要编辑当前展示帧，点“编辑这个姿势”。三维场景占据整个窗口，左上“步骤”与右上“调整”分别开关两侧栏，H 或眼睛按钮同时收起／恢复。全屏按钮进入浏览器全屏。侧栏收起时仍可以点选身体控制点、拖轴摆姿和旋转镜头；重新打开“调整”可输入数值。

如果原关键姿势已经摆好，只想调整两步之间的动画，请用“动画编辑”：拖底部时间轴，摆正中间画面，按 K 保存过渡关键帧。它直接参与播放，无需加入个人第 9–16 步列表，也不改写个人草稿。详见 [animation-editor.md](animation-editor.md)。

左侧“正式展示姿势”使用你确认的完整循环 **9 → 10 → 11 → 12 → 13 → 14 → 15 → 16 → 9**：后双撑、左侧三个变化、前双撑、右侧三个变化、接回同一个后双撑。正式数据来自 `托马斯/16.json`，保留保存的位置、朝向和锁定状态。步骤卡片与画面字幕标注原步骤编号，最后一个 09 与起点 09 完全相同。动作分解中点击步骤会暂停在对应关键帧；在“姿势编辑”中点击步骤后可修改，保存为自己的版本。也可以拖动时间轴后点“编辑这个姿势”，从当前过渡帧继续。

展开“手脚朝向与动作要点”，查看该步的掌面和手指、脚背和鞋尖、身体节奏与对应训练。所有说明在本地离线可读，打开外部视频才需要网络。“左侧三个变化”和“右侧三个变化”沿用你的阶段命名；说明中的支撑手指人物自身，按保存的锁手状态判断：第 10–12 步右手支撑，第 14–16 步左手支撑，第 09 和 13 步双手支撑。手掌和鞋尖方向沿用你微调后的姿势。

手机上侧栏轮流显示，载入模板或自己的步骤后自动收起，以便观察全身。再点“调整”可展开数值操作。

## 调整人物

点身体上的圆点，或从右侧“调整部位”选择骨盆、躯干、腰部、左右手腕、肘、脚踝和膝，共 11 个控制点。圆点的左右以人物自身为准。

- “移动”（G）：拖动彩色轴；右侧 X/Y/Z 可用厘米微调，Y 是高度。
- “旋转”（R）：拖动旋转环，或输入角度。膝部以膝盖为轴带动小腿与鞋，肘部以肘为轴带动前臂与手掌；旋转支撑侧肘部前，先取消对应手的固定。
- “腰部”：单独调整上身弯腰、扭腰和侧弯，角度相对骨盆计算。骨盆和躯干仍负责整体位置与身体方向。
- “左手固定／右手固定”：固定相应手掌的支撑位置，再移动或转动身体。
- “脚不穿地”：约束鞋底高度。四肢长度始终保持不变，超出可达范围会限制位移。
- “撤销调整”（Ctrl+Z）：撤销一次调整；一次连续拖动算一次。“看全身”重新对齐镜头，“从站姿开始”重设起点。

拖动控制轴时镜头保持固定。拖动空白处旋转观察、滚轮缩放。控制点与固定长度约束帮助摆姿，姿势是否符合你的托马斯标准由你判断。

选中部位后，右侧显示对应的操作说明。膝和肘保留原有移动方式，也可以直接旋转。腰部转动时，未固定的手臂随上身移动；固定的手掌保留支撑位置，继续遵守原有骨长与可达范围约束。

## 保存中间步骤

摆好后输入步骤名称，点“保存新步骤”。左侧“我的托马斯步骤”按顺序保存姿势；点击步骤载入，修改后点“更新此步骤”。上下箭头调整顺序，移除后可用“撤销移除步骤”恢复。个人步骤与正式展示分别存放，载入展示姿势不会删除已有步骤。

当前草稿和步骤保存在这个浏览器的本地存储中，关闭网页再打开可继续编辑。“导出 JSON”保存全部步骤；尚无步骤时保存当前姿势。“导入 JSON”将文件中的步骤追加到列表。更换浏览器或清理浏览器数据前，可用 JSON 备份。右上角“保存视图”导出人物 PNG，自动隐藏控制点和旋转环。

## 将微调用于正式展示

本次更新会把旧正式展示升级为项目中的 9–16–9 循环，旧版另行备份，个人步骤和当前草稿不改写。撤销升级后再刷新，会保留你恢复的旧展示。

在“我的托马斯步骤”保留当前 16 步或更多步骤后，点击“用于正式展示”，会优先按原步骤 ID 找到第 9–16 步，缺少匹配 ID 时使用列表第 9–16 项，再追加同一个第 9 步闭环；额外第 17 步不参与本循环。以后继续修改步骤，先点“更新此步骤”，再点“用于正式展示”同步新的保存值。仅有完整九步的个人库仍可以按九步列表发布。正式替换保存于独立的本地存储键，刷新后保留；“撤销展示替换”恢复上一次展示，个人步骤仍可继续编辑。

## 兼容工具：按五步半圈补齐镜像

前五步已经调整为前双撑 → 右侧移重 → 右侧单撑 → 换腿回撑 → 后双撑时，在“我的托马斯步骤”下面点击“补齐另一侧”。从后双撑继续，按第 4、3、2、1 步的镜像追加为第 6–9 步；第 9 步接回前撑。原来的五步保留。追加的是你实际保存的数据，预设模板没有参与重建。

五步自动补齐保留兼容触发条件：进入编辑器时，个人库恰好有五步、未记录 `five-step-half-v1` 完成标记，且每步的 `sourcePreset` 都与当前正式列表前五项 ID 对应，才会执行。早期五模板的 ID 与现在的 9–16–9 正式 ID 不同，因此早期五步库不会仅因刷新而自动补齐；需要时使用“补齐另一侧”按钮。主动撤销后保留完成标记，刷新不会自动重加。这个五步工具与下文第 12、11、10 步镜像补成第 14–16 步是两种独立流程。

镜像沿人物模型 X=0 的矢状面完成，左右手脚整组交换，骨盆、躯干方向、手腕、肘部、脚踝、膝部弯曲方向、掌面、鞋尖与支撑手一起镜像；地面锁定保持原值。相关侧栏说明随左右交换，镜头继续采用统一推荐机位，载入镜像不会切换观察方向。镜像后的步骤可以载入并继续优化，更新镜像不会修改其原姿势。

补齐前会在同一浏览器保存一份完整的本地备份。“撤销补齐”移除本次追加的步骤，仍可逐个恢复；已经生成的镜像不会重复追加。若需要更换浏览器，请在原浏览器导出 JSON，导入时保留镜像说明。

## 来源记录：第 9–13 步与右侧镜像

2026-10-05 导出的 `托马斯/13.json` 含完整 13 个步骤；`9.json` 至 `12.json` 的步骤内容与它一致。本次按你对新动作的说明，以第 9 步后撑、第 10–12 步一侧三个变化、第 13 步前撑为基础，将第 12、11、10 步的镜像追加为第 14、15、16 步。循环顺序为 **9 → 10 → 11 → 12 → 13 → 14 → 15 → 16 → 9**。新镜像交换全部手脚朝向、关节扭转、腰部角度和支撑手，原 13 步的数据及名称原样保留。

原始导出逐文件备份在 `托马斯/备份/2026-10-05T03-25-53-283Z-镜像前/`；完整结果是 `托马斯/已补齐-16步.json`，只含新增三步的文件是 `托马斯/右侧镜像-3步.json`。若手动导入，原来已有 13 步时只导入“右侧镜像-3步”，避免重复追加整套原动作。

在保存这 13 步的原浏览器刷新时，网页会核对原步骤 ID 和第 10–12 步实际姿态，先保存一份独立的浏览器原始数据备份，再只追加这三个镜像。已有步骤、当前草稿和标题保持原值；再次刷新不会重复补齐。已经拥有三个镜像的完整库不再改写或添加标记，其他步骤库不会被替换。后续已将确认的 9–16–9 循环用于正式展示。

正式替换前，连接的内置预览从导出文件恢复了完整 16 步，原来的一步旧草稿库另存于 `flare-saved-library-before-project-restore-20261005`；旧步骤保留在可恢复列表中。当时内置预览的原 13 步和新增三步已与完整结果文件逐项核对一致。这是该浏览器的恢复记录，不代表最新导出只有 16 步。

最新导出 `托马斯/16.json` 实际保存了 17 个动作，全部原文件已备份至 `托马斯/备份/2026-10-05T12-26-59-正式替换前/`。旧正式展示保存在该目录的 `旧正式展示.json`；新正式数据同时保存为 `托马斯/正式循环-9到16回9.json`。原导出文件均保持原样。

## 实现和验证

人物使用 Snow 来源的真实蒙皮网格和 20 根整理后的网页骨骼。`src/coach-motion.js` 以固定长度的双段 IK 驱动四肢，处理身体旋转、手掌支撑和鞋底高度，默认补帧先解析保存帧实际关节姿态；`src/pose-presets.js` 读取 9 个原始关键姿势并附加教学说明；`src/flare-sequence.js` 提供 9 秒与段内修正点插值，旋转使用最短四元数弧；`src/limb-arc.js` 按实际膝肘弯向与屈曲角连接姿态，默认脚绕髋、非支撑手绕肩，支撑手保留世界坐标目标；`src/transition-panel.js` / `src/transition-edits.js` 管理独立 K 帧界面与存储；`src/official-poses.js` 管理正式展示及独立备份；`src/pose-editor.js` 用 Three.js TransformControls 提供三维拖动；`src/pose-panel.js` 管理微调、撤销和 JSON 步骤库；`src/workspace.js` 管理侧栏和全屏，镜头避开已打开的桌面侧栏。姿势只控制运动人物，详细肌群仍使用独立解剖视图。

姿势文件格式为 `flare-pose-library`、版本 1，包含命名步骤、骨盆位置、躯干四元数、四肢端点及弯曲方向、手足旋转和锁定开关。独立腰部方向保存在可选 `torsoQuaternion`（相对身体方向），肘和膝的轴向扭转保存在可选 `elbowTwist` / `kneeTwist`（弧度）。旧文件缺省这些字段时保持原姿势，保存、镜像、展示插值均支持新字段。导入时先验证全部姿势，无效文件不会部分写入已有步骤。

当前 9–16–9 循环的针对性入口是 `tools/verify-saved-loop-ui.mjs`。只检查数据选择与存储迁移时使用：

```powershell
node tools/verify-saved-loop-ui.mjs --module-only
```

该模式不启动浏览器，核对原第 9–16 步接回同一个 9、ID 优先选择与导入 ID 改变后的按位置选择、独立备份、撤销和刷新幂等、个人库不改写及十三步镜像兼容。它不检验人物渲染、动画物理或全部关节编辑。

可选的实际 UI 检查要求本机 Chrome 和 Codex 提供的 Playwright 运行库可用，并由 `http://127.0.0.1:8810/` 提供最新构建页面。先运行 `npm run build`；若该端口尚未启动服务，在一个终端运行 `npm start`，再在另一终端运行：

```powershell
node tools/verify-saved-loop-ui.mjs
```

工具使用独立浏览器上下文，注入对照库，不修改用户正在使用的浏览器数据。范围为旧正式缓存升级、备份和撤销、17 步对照库与草稿原始字节保留、九个实际关键帧、四阶段跳转与固定镜头、采用个人循环及一个手机侧栏场景。报告和截图在 `output/saved-loop-9-16/`，纯模块报告为 `module-verification.json`，UI 报告为 `verification.json`。

以下入口保留了旧夹具或旧流程断言，属于历史检查，**不能作为当前 9–16–9 版本通过的证据**，也不应直接列为本版验收命令：

| 历史入口 | 与当前版本不同的断言 |
| --- | --- |
| `npm run verify:presets` | 固定 `托马斯/5.json`、原第 1–5 步加镜像、旧九 ID 与前撑起始阶段。 |
| `npm run verify:sequence` | 固定前撑 0 秒、后撑 4 秒、前撑重复 8 秒；当前为后撑 0 秒、前撑 4 秒、后撑重复 8 秒。 |
| `npm run verify:official` | 假定 `firstFiveIds`、同名个人九步自动采用、空存储不写键及只有两个正式存储键。 |
| `npm run verify:demonstration` | 仍要求同名个人九步自动采用和仅两个正式键变化；当前使用独立升级备份与标记。 |
| `npm run verify` | 按固定阶段索引检查旧前撑／后撑时间和方向。 |
| `npm run verify:workspace` | 点击旧预设 ID `flare-right-high-v`，要求旧指导文字和视频时间参数。 |

`verify:pose`、`verify:motion`、`verify:asset` 是一般编辑器、运动约束和资产复核入口，范围不同于上述正式循环检查。此前正式循环的文档收束只复核纯模块入口与构建；本轮动画编辑的定向检查见 [animation-editor.md](animation-editor.md#验证入口)，没有重跑这些一般入口或全量测试，不能把旧结果当作当前版本的全量通过声明。

9–16–9 功能交付时只检查了新九帧与保存来源逐项一致、精确闭环、骨长与支撑漂移、缓存升级与撤销、个人数据保留，并构建和确认浏览器展示。来源与骨架记录位于 `output/official-loop-9-16/`，针对性 UI 记录位于 `output/saved-loop-9-16/`。`output/official-sequence/`、`output/flare-sequence/`、`output/pose-presets/` 保留此前正式版本的检查，不能证明本版全量通过。连续过渡仍遵循原有 IK 可达性约束，整数关键姿势的数据保留用户原值。
