# 动画编辑：自己 K 中间帧

在本地页面左侧选择“动画编辑”。沿用姿势编辑中的身体圆点、彩色轴和旋转环，不需要换软件。也可以在“动作分解”暂停后点“编辑动画 · K帧”，从当前画面开始。

画布下方的时间轴始终可用，收起侧栏后仍可操作。白色菱形是已保存的原第 09–16 步和重复第 09 步；蓝色菱形是新增中间关键帧。原有九个节点保留，新增帧只控制它所在的两步之间的过渡。

1. 拖时间轴到问题画面，或在左侧选一段过渡，从中点开始检查。
2. 点身体控制点，像之前一样移动或旋转。肘、膝的移动用于调整弯曲方向，旋转会带动前臂或小腿；腰部可独立弯腰。右上“调整”可打开厘米和角度微调。
3. 按 **K**，或点画布下方“保存关键帧 · K”。再次停在已有蓝色帧上，K 会更新该帧。保存后，从前一个关键姿态到这帧、再到后一个关键姿态的两侧过渡都会重新生成；提示显示此次影响的秒范围。若附近另有已保存帧，重建范围以它们为界。单段预览和完整播放使用同一结果。
4. 按 **空格**播放／暂停；**← / →** 每次前进或后退 1/60 秒。下方可选择“当前段循环”或“完整循环”，速度可降至 0.1×。

右侧顶部“关键帧之间自动补帧”可选 **线性 · 匀速** 或 **平滑 · 缓入缓出**。线性模式在相邻两个已保存帧之间按时间匀速插值；平滑模式沿用原步骤之间的缓入缓出。你只需调整并 K 关键姿势，中间画面自动生成；新增帧会把所在过渡分成更短的区间。设置立即用于单段和完整播放，可撤销、刷新恢复，也会随过渡 JSON 导出。已有过渡数据继续使用原平滑模式，关键帧保存值保留。

键盘快捷键在输入框以外生效。G 移动、R 旋转，Ctrl+Z 撤销当前姿势调整。白色原节点处禁用修改和 K 帧；若确实需要改原节点，继续使用原有“姿势编辑”和“用于正式展示”。

先少量补帧：在明显出错的位置摆一帧，再慢放观察两侧；仍不对时再补帧。无需把每一帧都重新摆一遍。当前没有曲线编辑器或自动判断正确托马斯动作，路线和弯向由保存的姿势指定。

## 保存、删除与备份

关键帧保存在当前浏览器，刷新后保留。未按 K 的姿态另作暂存，可在左侧“回到暂存的调整”继续；暂存不会参与播放。左侧每个中间帧右侧的 × 可以移除，“撤销过渡修改”可恢复上一次保存、更新、删除、设置或导入；当前姿态的 Ctrl+Z 与已保存帧的撤销分别处理。

右侧“导出过渡 JSON”备份当前过渡帧、设置与暂存；“导入过渡 JSON”恢复这份备份，文件需在 2 MB 以内。过渡备份与个人步骤 JSON 分开，导入前会验证全部内容和原节点，不会部分写入。

“路线与启用设置”中的“启用过渡调整”可停用新过渡并对照旧直线版本，已有帧保留。更换正式展示时，过渡帧按原节点数据分开保存：另一组姿势的修正不会误套过来；切回同一组原节点可恢复对应过渡。原始导出文件、个人步骤库和原姿势草稿不由动画编辑改写。

## 当前过渡路径

默认“四肢过渡路线”采用 **沿关键姿态 · 推荐**。补帧先读取相邻保存姿态在现有骨长、锁手和地面约束下实际解出的膝肘位置及弯曲平面，再在身体局部坐标中连接这些姿态。这样两侧过渡趋近保存帧实际显示的姿势，关节接近伸直或弯向相反时不会因弯向向量抵消而突然切换备用方向。

脚部围绕运动髋部走圆弧，非支撑手臂围绕运动肩部过渡，减少端点在世界坐标中连直线造成的无意折叠；支撑手继续采用世界坐标中的保存端点和原锁定约束。鞋底需要避地时，在相同髋踝半径的地面圆周上调整。新增 K 帧保存的是编辑时实际姿势，补帧不加入仅影响显示、无法保存的临时骨骼旋转。

脚与非共撑手臂的屈曲角按两端实际保存姿态插值，再依据固定上、下骨长计算端点距离，减少近伸直姿态中直接插值距离造成的急弯。两端均锁定的支撑手保留世界坐标腕目标，肘部屈曲由现有解算器求出。采样不依赖上一帧，正播、倒拖和跳转到同一时间会得到同一姿态。

“路线与启用设置”可选择“原直线 · 对照”。已有 `arc` 过渡设置沿用推荐路线，不改保存帧的数据；`linear` 设置和停用过渡调整仍可回到旧算法。这不修改原节点或新增帧的保存值，也不替代手工 K 帧。

补帧速度与四肢路线分别设置：“线性 · 匀速”不等于手脚必须走直线，可配合默认推荐路线；若要直线目标，另选“原直线 · 对照”。人物和手脚朝向仍用四元数最短弧旋转，骨长、锁手与地面约束继续生效，因此实际关节位移不保证严格匀速。线性模式经过关键帧时速度方向可能突变；若选错绕行或弯向，在问题区间补一个关键姿势来指定路线。

两端旋转的方向仍可能存在多种路线，增加中间帧可以指定经过的位置和弯向。手掌锁定、固定骨长和地面约束继续由已有解算器处理；不能据此宣称动作符合物理或所有姿势无穿模。周期仍为 9 秒，其中原第 09 步在 8–9 秒保持原有闭环停顿；编辑时间轴覆盖实际过渡的 0–8 秒。

## 验证入口

针对本功能的检查：

```powershell
node tools/verify-transition-sampling.mjs
node tools/verify-transition-rig.mjs
node tools/verify-transition-storage.mjs
node tools/verify-transition-ui.mjs
```

仅检查线性／平滑补帧切换时，可运行 `node tools/verify-transition-ui.mjs --interpolation-only`，覆盖旧数据、实际人物插值、暂存、保存、撤销、刷新与备份恢复。

仅检查实际 K 帧对两侧补帧的影响时，可运行 `node tools/verify-transition-ui.mjs --keyframe-spans`，覆盖实际膝部调整、K 保存和更新、两侧趋近保存姿势及骨骼朝向、下一 K 帧限制影响范围和刷新恢复。

本次实际骨架的旧／新对照及冻结姿态保存在 `output/playwright/keyframe-interpolation-before.json`、`keyframe-interpolation-after.json` 和 `keyframe-interpolation-fixture.json`。保留这些文件时，`node tools/verify-keyframe-interpolation.mjs --after` 可重放对照，检查相反弯向、近伸直姿态与弯向控制点退化的 K 帧，以及精确保存帧、骨长、锁手、地面及旧直线模式。无参数命令会覆盖本地 fixture 和 before，只测量当前实现，不能替代这份冻结旧算法记录。`output/` 不进入 Git，换机重放对照需另行保留这三份 JSON；缺失时仍可运行上述采样、骨架、存储与 UI 定向检查。

前两项分别检查采样原始值与实际 Snow 骨架；存储检查确认关键帧隔离、禁用、导入与旧数据保留。UI 检查要求先 `npm run build`，8810 本地服务和本机 Chrome 可用，使用独立浏览器上下文。截图与报告放在 `output/playwright/`，不触碰用户当前浏览器数据。检查范围为本功能，不是编辑器或动作物理的全量验收。
