# BodyParts3D 绑定枢轴与动作重定向

> 历史试验记录：以下描述此前 BodyParts3D 自动绑定与体表展示的实现、测量和检查，不是当前默认动作人物。当前 `src/viewer.js` 使用 Snow 的 `createCoachMotion`；详细解剖在独立视图展示。当前人物与复现见 [friendly-coach.md](friendly-coach.md)，正式循环见 [flare-pose-presets.md](flare-pose-presets.md)。以下旧时间轴、网格数量和验证结果按原记录保留，未在本次文档对齐中重跑。

此前试验的动作页使用与静态解剖页相同的 637 个 BodyParts3D 4.0 肌骨结构，以及可选的原始 Skin 体表。`src/atlas-motion.js` 复制原始几何并添加 GPU skin 属性，肌骨结构按八个功能肌群、其他肌肉、骨骼合并为 10 批 `SkinnedMesh`；Skin 独立合并为第 11 批。静态几何和原始 position/normal/index 数值保持不变。

当时加载 Skin 默认仅显示完整、不透明体表。只有选择局部肌群并进入 `reveal` 后，才显示相应内部肌肉与淡骨骼；局部皮肤窗口由调用方的体表材质控制。完整皮肤是该轮试验的展示基线，覆盖更早资产索引中把 Skin 当透明轮廓参考的建议。

`flare-rig.js` 仅提供周期、躯干方向、支持手与腿的摆动方向。它生成的几何人体不进入动作场景。动作使用下面测得的源模型比例重新求解。

骨盆 root 到肩中心为 0.504795 m，肩关节间宽度为 0.319952 m，髋关节间宽度为 0.174330 m。颈基部到头枢轴为 0.093928 m。

## 绑定方式

20 根动画骨独立位于 rest 枢轴上。每根的逆绑定矩阵为 `T(-restPivot)`。姿态矩阵是 `T(targetPivot) * R`，因而顶点经该骨转换为 `targetPivot + R * (vertex - restPivot)`。缩放恒为 1。

每块骨骼几何的所有顶点均使用一个权重为 1 的动画骨：肱骨跟上臂，尺/桡骨跟前臂，股骨跟大腿，胫/腓骨跟小腿，腕掌指骨跟手，足骨跟脚。骨盆与骶骨跟骨盆；肋骨、胸骨、胸腰椎跟躯干；颅骨跟头部。髌骨使用独立刚性辅助骨，在大腿、小腿旋转之间取中间方向。肩胛骨与锁骨保持刚性，跟躯干方向，不用软顶点权重将骨头扭弯。

肌肉先由解剖名称限定可用体段，再按源骨轴上的位置生成最多三项权重。这样不会因“离哪个关节最近”而把胸部顶点错误分配到对侧手臂。肩、肘、髋、膝、腕、踝附近平滑过渡，远离关节的区域保持主所属体段。

| 肌肉 | 当前权重范围与处理 |
| --- | --- |
| 胸大/小肌 | 躯干 → 同侧上臂，内侧胸壁保留躯干权重 |
| 三角肌、肱二/三头肌 | 肩胛体段 → 上臂 → 前臂 |
| 肩袖、大圆肌 | 肩胛体段 → 上臂 |
| 斜方肌、菱形肌、前锯肌、提肩胛肌 | 主要跟肩胛/躯干，上臂影响限制为 16% |
| 前臂屈伸肌 | 上臂 → 前臂 → 手，末端手部区域跟手 |
| 髂腰肌（FJ1431/M、FJ1422/M）、臀肌 | 骨盆 → 同侧大腿，腰/髂部主体保留骨盆/躯干方向 |
| 髋内收、股四头、腘绳肌 | 骨盆 → 大腿 → 小腿 |
| 小腿肌 | 大腿 → 小腿 → 脚，跟腱/足部末端平滑过渡 |
| 手、足内在肌 | 随整只手或脚，保留来源几何的形态 |

腹外斜肌等躯干肌在当前动作里随同一躯干 frame。骨盆与躯干当前使用相同旋转，因而在二者之间分配权重会得到相同变换。后续若独立驱动腰部弯曲，腹外斜肌应在骨盆、腰部和胸廓间混合，斜方肌应在颈、胸廓、肩胛间混合，髂腰肌应在腰/骨盆与大腿间混合；不能把这些整体肌肉全部固定到某一个肢段。

Skin 是覆盖全身的单个来源网格，不能按整块网格绑定到骨盆。它的每个顶点先比较源躯干与同侧四肢胶囊的归一化距离，再按实际骨轴上的投影生成最多四项权重。躯干/上臂、上臂/前臂/手、骨盆/大腿、小腿/脚均有连续过渡。头颈和身体中心保留躯干变换，手脚远端保留源几何的形态。Skin 与肌骨批次使用同一个 20 骨 Skeleton。

## 支撑与脚部

支持掌的 X 为 ±0.21 m、Z 为 0。源模型的手指有自然弯曲，不通过拉平几何来模拟接地。掌参考点由第三掌骨中心确定，指轴由中指末节到掌中心确定，掌法向近似取源 +Z 在指轴正交平面的投影。支持时指轴朝 -Z，掌法向朝 -Y。对实际手顶点检查最低位置后，掌参考点高度约为 0.082 m，最低顶点保持约 0.008 m。

支持手腕由这个刚性手变换计算，再用源上臂/前臂长度解两段 IK。躯干高度根据手臂可达范围连续调整，抬手段逐渐释放约束。空中手可调整自由路径；支持手保持精确固定。

两腿按驱动器节奏前后扫动，每腿约 63° 外展，保留源大腿/小腿长度并避免重定向后两股骨互穿。脚保持原有几何形态，足底方向水平；通过足区受影响顶点的保守范围检查地面，必要时抬高腿的方向，保持所有体段长度。

0 秒为胸朝地面的双手支撑，1.6 秒为右手支撑，4 秒为胸朝上的双手支撑，6.2 秒为左手支撑，8 秒回到 0。周期是教学安排，不是动作捕捉时序。

## API 与验证

```js
const motion = createAtlasMotion({
  parts,             // THREE.Mesh[]; userData.part 为带 hotspot 的 manifest part
  skinParts,         // 可选 THREE.Mesh[]，skin-manifest.json 的完整 Skin
  driver,            // createFlareRig()；不把 driver.group 加入场景
  materials: { muscle, bone, active, ghost, skin },
});
scene.add(motion.group);
motion.update(time);  // 0..8 秒，循环
motion.setHighlight('shoulders');
motion.setLayer('skin');     // 默认完整体表
motion.setLayer('reveal');   // 体表 + 当前肌群 + ghost 骨骼
// muscles / bones / combined 可用于完整内部结构查看
// motion.skinMeshes 是独立 SkinnedMesh[]，可为其材质加入局部剖开窗口
const metrics = motion.getMetrics();
```

`getMetrics()` 返回 `source: 'BodyParts3D 4.0'`、`automaticallyBound: true`、支持手、支持掌漂移、源长度与实际长度（左右 flat keys 和 torso）、关节点、足区最低高度、胸面方向、保守 bounds 与 GPU 绑定统计。`surfaceVertices` 是新增体表顶点数 22,902；`skinning.originalMeshes` 始终指 637 个原肌骨结构，`skinning.weightedVertices` 为其 873,641 个顶点。体表数量单独记入 `skinning.surfaceVertices` 与 `surfaceMeshes`。

801 个全周期采样验证：支持掌漂移最大 1.6e-16 m，体段长度误差最大 2.5e-16 m，足区保守最低高度 0.0101 m；左右臂与左右腿保持分离，0/8 秒完全衔接。全部 182,066 个骨骼顶点的首权重均为 1；全部 873,641 个顶点权重和为 1。源静态几何没有增加 skin 属性。

四个关键相对全部顶点按实际 Skeleton GPU 矩阵复算，整体最低 Y 约为 0.008 m，足区与保守高度吻合。指标中的 `bounds` 是受影响顶点 bounds 的角点变换联合，可能包含不存在的 AABB 角点，因此负的 bounds ymin 不能解释为真实顶点穿地。页面的四相、侧面与背面仍应进行浏览器目视检查。

新增 Skin 后再次检查 801 个姿态，支持掌与体段长度仍保持上面的误差范围，含体表的足区保守最低高度为 0.00875 m。对 81 个姿态的全部 22,902 个实际体表顶点复算，最低 Y 为 0.01169 m。体表权重和误差不超过 3.73e-8，16 个头颈、躯干/骨盆和左右四肢骨获得有效体表权重。默认 `skin` 不显示内部批次；`reveal` 仅显示 Skin、选中肌群与 ghost 骨骼；`bones` 仅显示骨骼。所有来源静态几何仍无 skin 属性。数值检查不能替代肩部、腹股沟和换手相的外观检查。

此模型使用真实来源几何与自动生成的动画权重。它保留原始骨骼、肌肉外形，用于动作与肌群关联示意，未模拟肌肉收缩或软组织物理。
