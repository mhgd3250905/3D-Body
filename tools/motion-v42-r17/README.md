# Flare v42 / R17 循环起手修复

R17 修复用户在 R16 循环首尾附近看到的右支撑肘抖动；另存新版，R15、R16 与既有预览完整保留。数值核对通过，仍待用户复核观感。

实际问题出现在循环后约 2.97%，而非 100%/0% 姿势不闭合。R16 起手的游离臂提前启用时序微调，共享双臂可达约束把身体下压约 4.53 mm，使右支撑肘短暂从约 177° 弯到 164.07°。动画烘焙与随机拖动一致，AnimationMixer 的重复循环也复现相同轨迹。

本版只新增 `armTakeoffBlendPhase: [.055, .08]`：起手前 5.5% 使用原时序，5.5%–8% 平滑接入微调；另一半周期同样处理。R16 已修复的落手窗口及其余动作保持。制作代码继承 R16，继续采样同一冻结 R14，避免重复叠加变形。

两人体实际 GLB 各 10001 相位检查：0%–8% 右肘为 176.7354°–177.0015°，50%–58% 左肘最低 176.7261°。两段支撑腕位置、修改区外骨位置、R16 原落手两窗骨位置均保持；肩颈相对躯干最大差 0.0000659 mm。两人体各 1081 相位的骨长、蒙皮和接地检查通过。最终 GLB 与已审计 trial01 逐字节相同。

循环位置缝为零；线性烘焙仍非数学上的 C1 曲线，严格首尾右肘速度差约 0.04644 m/s。此次消除约 13° 的起手回弯，不将有限检查扩大为全动画平滑或用户验收。

## 复现

恢复冻结清单中的 R14 输入，安装仓库与 `app/scene` 的锁定依赖，在新目录运行：

```powershell
node tools/motion-v42-r17/bake.mjs --out output/flare-v42-r17-rebuild-new
node tools/motion-v42-r17/verify-release.mjs --dir output/flare-v42-r17-rebuild-new
node app/scene/tools/integrate-v42-r17.mjs --from output/flare-v42-r17-rebuild-new
node app/scene/tools/verify-v42-r17-assets.mjs
```

默认输出为 `output/flare-v42-r17-20261017`；烘焙拒绝覆盖已有批次。1.35 秒、541 帧、22 骨/44 轨及 0–9 教学时钟保持。审计脚本在 `audit/`，冻结证据在 `releases/r17-evidence/`。

[R16 / R17 对照](http://127.0.0.1:8877/r17-preview/)默认暂停 2.97%，可播放完整循环或慢放 95% → 0% → 8%。两侧使用实际 GLB 并核对 SHA。App 交付记录与版本标签将在本轮保存时绑定；R17 待用户复核。
